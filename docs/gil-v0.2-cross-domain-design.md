# GIL v0.2 候选：跨领域设计依据

日期：2026-11-01。状态：规范修订提案，不是已实现能力。

## 1. 本轮目标

以临床运营和游戏增长分析检验 GIL 的通用性。不是给 OptiMed 写接入器，也不是给 Brando 补业务流程。两个项目只提供场景压力；领域术语、业务阈值和内部流程不直接进入 Core。

本轮交付：候选语义合同、双场景验收、与既有规范的关系。没有新增解析器、服务、认证或运行时。

## 3. 对前轮分析的纠偏

1. OptiMed 的四个 DecisionStatus 是业务决策结果，不是四值真值。GIL 保留三值逻辑，不把 NEEDS_REVIEW 当第四个真值。
2. Brando 的 D0/D1/D2/DINF 反映能力与输入可达性，不是统一证据强弱，更不是因果证明等级。
3. 看过几个文件不能证明整个业务项目“没有”某能力。本轮只引用实际找到的约束，不以搜索缺失作为架构缺失证明。
4. GIL 不是自动要求人类编辑 DSL。结构化 UI、受控 JSON、自然语言投影都可以是前端；规范对象仍是精确 AST/工件。
5. 原型存在不等于端到端可运行。当前 checker、求值器、授权门的支持范围不同，必须显式列出能力，而不能说某层“完整”。

## 4. 层级落点

| 概念 | 所属层 | 不承担的职责 |
|---|---|---|
| 测量口径、主张类别、带原因的求值报告 | Core 可选 profile | 不规定药厂或游戏业务阈值，不包含账号权限 |
| 来源谱系、观察快照、覆盖和新鲜度描述 | Workspace | 不把可访问来源自动变成可信事实 |
| 补值、争议裁决、口径映射的精确接受 | Exchange | 不把接受变成证明或执行许可 |
| 用途、字段、接收方、外部效果的授权检查 | Delegation | 不从模型分数或“已审核”推断 Grant |
| 统计/因果方法、独立性、凭证失效和影响传播 | Assurance | 不自动判断临床合法性或统计识别正确性 |
| 业务状态投影与执行 | 宿主适配器 | 不改写 Core 真值表 |

## 5. 什么不进入通用规范

不固定 ClinOps 的 Issue/Task 状态机、CRA/CTM 名称、USDM/CDISC 映射、游戏 DAU/TGI 阈值、Brando C/D 档枚举、具体 DID/PSM 算法或 SQL 表名。它们由领域 profile 和外部验证器解释。

## 6. 使用方式

宿主保存领域对象和权威状态。GIL 为一次决策提供合同：输入引用、口径、允许的主张、求值、审阅义务、精确接受、授权与证据绑定。Agent 只能提出候选或调用已声明的适配器。

本轮候选模型见 [语义合同](gil-v0.2-semantic-contract.md)，成对验收见 [双场景案例](gil-v0.2-dual-scenario-acceptance.md)。这些类型框属于规范模型示意，不是 `.gil` 可解析语法。
