# GIL v0.2 候选：双场景验收

日期：2026-11-01。状态：设计验收合同，未执行自动测试，不是生产验证。

全部对象、数值、人物与动作均为合成夹具。使用两个场景检验同一语义规则；不复制企业原始数据，不固定行业阈值。

## 1. 两个贯穿场景

**C：临床运营监督。** 从版本化方案提取一条访视要求，适格人员确认适用范围；导入独立执行观察，计算偏差候选；确认发现后创建事项，补证并独立复核。方案要求不证明访视已执行，关闭源端记录不关闭人工事项。

**G：游戏增长分析。** 固定回流人群与留存观察窗，从登记来源生成分析；分别给描述、关联与因果候选；冻结情景测算，审阅结论与建议；任何外发、投放或预算调整单独授权。报告完成不证明增长发生。

共同流程：来源 → 候选合同 → 精确接受/发布 → 冻结观察 → 判定及缺口 → 审阅 → 受限行动 → 回执验证 → 变更/挑战。

## 2. 成对正反案例

下表“正确”指候选 profile 要求的结果，不代表当前原型已经给出此结果。

| ID / 规则 | C：临床运营 | G：游戏增长 | 正向验收 | 反向验收 |
|---|---|---|---|---|
| X01 要求≠观察 | 方案写“访视应完成”，无执行记录 | 计划写“提升留存”，无结果数据 | 保存要求与观察为不同工件 | 从要求生成“已完成/已提升”必须拒绝 |
| X02 口径身份 | screened 与 enrolled 不同 | 账号数与去重人数不同 | 相同合同且时间关系明确可比较；显式映射保留损失 | 同名或相似数字直接混算必须拒绝 |
| X03 窗口与水位 | 预期访视窗未结束，来源只覆盖其前半段 | 回流队列还未走完28日观察窗 | 标记未成熟窗口与覆盖缺口 | 判“漏访/28日留存下降”不得通过 |
| X04 闭合缺失 | 范围、映射、相关记录与水位均核清 | 登记全集查询覆盖完整人群和分区 | 仅在该闭合范围内判 ConfirmedAbsent | 断连、部分导出、不可读不得判不存在 |
| X05 真值与审阅 | 已确定一条件为False，另有相关来源冲突 | 已确定预算不符，另有相关口径争议 | 可报告False，同时保留审阅义务 | `False AND Unknown` 不得清除争议；无关争议不得阻塞所有工作 |
| X06 主张类别 | 执行延迟与某中心相关 | 触达后留存较高 | 输出关联结论及替代解释 | 无识别设计不得称中心责任/召回净效应 |
| X07 不确定性类型 | 某统计估计给置信区间；另有运行情景范围 | low/mid/high 连乘包络与抽样分位数 | 输出类型、方法、参数与假设 | 情景包络不得标95%置信区间；模拟分位数不得隐去相关性假设 |
| X08 证据独立性 | protocol JSON 和SoA来自同一原件 | 图表和摘要来自同一次查询 | 追溯共同根，标明独立性维度 | 两个文件不得计成两份独立证据 |
| X09 接受≠证明≠许可 | 人确认适用要求，不批准自动关单 | 人接受测算假设，不批准预算调整 | 分别保存Accept、Attestation、Grant | 从“认可方案/统计显著”推导执行权必须拒绝 |
| X10 用途与字段 | 允许读方案，不允许发送合同金额给模型 | 允许聚合分析，不允许外发玩家级明细 | 本次请求固定用途、字段、接收方并检查当前权限 | 读取许可、文件生成不得授权外发；来源文本指令不得扩权 |
| X11 精确版本失效 | 方案修订影响该访视要求及其关闭证据 | 去重映射修订影响留存与情景测算 | 新工件、新测量、受影响链重评；历史保留 | 旧批准不得直接复用；无关结论不得全局作废 |
| X12 降级不伪装实时 | 模型不可用，确定性规则仍可运行 | 数据库断连，可用获准历史只读快照 | 标明能力失败、水位和允许的降级；保留独立路径 | 静默拿旧数据报当前结果必须拒绝；不得由断连直接推断Stale |
| X13 回执≠业务完成 | 生成复核材料，不等于事项合法关闭 | 生成投放方案，不等于发布或增长实现 | 业务完成由专门回执/验证证明 | 文件存在、exit=0、Task complete 不得当业务成功 |
| X14 超时与恢复 | 写入请求超时，是否已提交未知 | 外部发布请求超时，是否已发布未知 | 先核对、幂等或暂停；恢复亦需授权与验证 | 盲目重试、把补偿称完全恢复必须拒绝 |
| X15 有边界偏好 | 在满足硬约束的方案中选较低成本 | 在获准且符合人群限制的实验中选较高预期收益 | 仅对语义可比、满足必需条件的候选排序 | Unknown 不得当最差；收益不得抵消隐私/合规约束 |
| X16 适配器状态 | 投影 NEEDS_REVIEW，而命题可能已False | 能力档D1、输出为描述性且无外发权 | 保留各原始维度及版本化投影规则 | 档位/业务ALLOW不得反推True、Pass或Grant |

## 3. 验收运行要求

未来测试夹具至少包括：输入工件及hash、语义profile、测量与观察合同、主张类型、假设、相关审阅、动作请求、预期真值/诊断/门禁结果、反例及来源依赖。

每一行至少有一例可继续和一例必须拒绝或降级。拒绝原因须指向缺少的合同或违反的边界，不能统一输出“权限不足”或“数据不足”。领域适配器须说明这些结果怎样投影到业务UI。

无外部系统情况下只能声称通过合成验收。真实身份、时间、水位、签名、外部回执与持久化需要另外的集成验收。

## 4. 当前原型映射

| 相关能力 | v0.1 原型现状 | 对本轮案例的意义 |
|---|---|---|
| 三值、open、ambiguous、偏好 | 部分可求值；checker/运行时支持边界不同 | 可借机制，不能宣称X05/X15端到端符合 |
| sources.ts 覆盖与缺失 | 有有限闭合缺失模型 | 可复用概念，尚无通用测量合同与水位联动 |
| assurance/delegation | 过程内、可选凭证绑定、无生产身份 | 支持合成版本与门禁案例，不保证X09–X14生产符合 |
| Workspace hash与快照 | 过程内工件及版本引用 | 有来源链基础，未实现通用派生图/独立性判定 |
| 统计与因果 | 没有通用方法合同或真实验证器 | X06–X08为新增规范，不宣称算法已实现 |

现有测试通过只证明旧profile的回归。X01–X16均须在以后实现中单独测试，当前状态统一为“设计验收待实现”。


## 5. 固定文档夹具与唯一预期

这些是可手工判分的规范夹具，不是已执行的自动测试。C/G只改变领域名称，输入结构和预期规则一致。`Deny`指本次请求不能进入行动，不表示命题为False。

| 夹具 | 固定输入（C / G） | 唯一预期 |
|---|---|---|
| F01 闭合零命中 | C访视/G触达：Complete、可读、映射有效、搜索覆盖目标对象及时间、水位覆盖已成熟窗口、适用性确定、闭合依据已给、命中0、无冲突 | observation=ConfirmedAbsent；缺失命题=True；业务行动仍需另判 |
| F02 闭合但命中 | 同F01，命中1 | observation=Observed；缺失命题=False；不得输出ConfirmedAbsent |
| F03 部分覆盖 | 同F01，但Partial；已搜可读子范围，命中0 | observation=NotObserved；缺失命题=Unknown；issue=COVERAGE_INCOMPLETE；依赖缺失证明的行动=Deny |
| F04 来源不可读 | 同F01，但Unavailable且检索未完成 | observation=UnableToDetermine；truth=Unknown；issue=SOURCE_UNAVAILABLE；freshness=NotEvaluated（未提供时效政策） |
| F05 直接冲突 | C执行状态/G触达状态同一绑定：源A=True，源B=False，无裁决，相关性规则v1 | truth=Unknown；issue=INPUT_CONFLICT；review=Required；依赖该绑定的行动=Deny |
| F06 逻辑已收敛 | 同F05，目标是False AND conflictedBinding | truth=False；INPUT_CONFLICT和Required审阅仍保留；行动=Deny（已违反前置条件） |
| F07 无关冲突 | 同F05，但目标仅为独立常量True；规则v1判冲突不相关；本次Grant及其他门均有效 | truth=True；本次review=None；action=Allow；原冲突记录不删除 |
| F08 同合同但时间未对齐 | C中心完成率/G回流留存：测量合同相同；请求同一as-of横比，快照水位不同且无对齐工件 | comparison=Rejected；issue=SNAPSHOT_ALIGNMENT_REQUIRED；不产出差值 |
| F09 同合同跨期 | 同F08，明确请求跨期比较，合同固定两个水位；两快照Complete、映射有效、适用性确定，两个观察窗均成熟且水位覆盖 | comparison=Allowed；输出标注跨期，不声称同期比较 |
| F10 包络标签错误 | C运行情景/G机会测算：low/mid/high连乘，输出称95%置信区间 | validation=Rejected；issue=UNCERTAINTY_KIND_MISMATCH；发布该标签=Deny |
| F11 相关冒充因果 | C中心延迟/G触达留存：仅分组差异；无识别设计；请求Causal主张 | claimValidation=Rejected；issue=IDENTIFICATION_REQUIRED；可另建Associational候选，不静默改写原请求 |
| F12 认可但无外发权 | C核实材料/G增长报告：Accept有效、验证通过；Grant只允许内部分析；请求外发 | truth不受影响；action=Deny；issue=EFFECT_NOT_GRANTED |
| F13 同源两文件 | Cprotocol JSON+SoA / G图表+摘要：两工件同lineage root；要求两份来源独立证据 | independence=NotEstablished；issue=SHARED_SOURCE_ROOT；依赖该独立性要求的行动=Deny |
| F14 未知候选排序 | C方案/G实验：A所有必需条件True；B一项必需条件Unknown；请求偏好排序 | eligible={A}；B=Pending；完整排序=Unavailable；不得称B收益更差 |
| F15 发布超时 | C记录提交/G报告发布：请求发送后超时，无回执，副作用状态未知 | execution=Unknown；retry=BlockedUntilReconciled；issue=OUTCOME_UNCONFIRMED |
| F16 有范围的降级 | C模型故障/G查询断连：获准只读旧快照，水位已标，freshness政策判Stale；请求当前事实 | currentClaim=Unknown；issue=LIVE_INPUT_UNAVAILABLE；允许历史报告且标Stale；外部写入=Deny |

| F17 命中但冲突 | 同F02，命中1但同绑定存在未裁决矛盾来源 | observation=UnableToDetermine；truth=Unknown；INPUT_CONFLICT；review=Required；不得ConfirmedAbsent或Observed |

剩余成对规则采用同样的文档夹具形式扩展。任何未来实现声明应明确已通过哪些X/F案例，而不能以部分案例通过宣称整个profile符合。
