# Phase3：授权与审计

状态：用户已授权并完成（2026-10-26）；100项自动测试通过，模拟身份及过程内授权范围，未实现实际证据验证或持久化。

## 目标

在Core模拟与临床角色之间增加默认拒绝的授权门，使协调员提交、CRA复核、CTM关闭的政策可重放；Agent不能批准或关闭。

## 步骤

1. 明确模拟身份适配器及Grant作用域、deny优先、有效期、撤销、预算。
2. 定义精确计划批准与当前版本判定；旧快照接受不等于当前授权。
3. 把解释回答固化成显式计划工件，保证计划、来源与Core状态版本绑定。
4. 实现授权判定Allow/Deny/Escalate，保持Core求值器无角色依赖。
5. 授权通过后才调用模拟器；拒绝不提交状态、不产生虚假成功日志。
6. 生成内容寻址尝试/拒绝/成功审计事件，保留主体及Grant引用。
7. 扩展CLI和测试，验证撤销、预算、跨中心、Agent拒绝和版本冲突。

## 验收

- A19–A23的权限部分可重放，deny优先且预算不被拆分绕过。
- A25/A26对应接受与批准的版本边界明确，不继承陈旧授权。
- 没有Grant的closeFinding即使Core条件真也被拒绝。
- 既有72项测试不回退。

## 边界

仍为合成数据和模拟身份；不声称真实认证，不接临床系统。实际Attestation及失效依赖图在Phase4实现；不能用受调用者控制的Bool冒充真实审核证据。
